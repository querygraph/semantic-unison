# Named producer-interruption fixture

The current production copy path uses `SupervisedExternal`, which gives each external copy/merge command its own supervised process group. The old validation-path fixture killed a counter PID and the client group. That cannot establish ownership or native wait4 settlement of the separately supervised helper.

The source successor preserves the complete- and partial-stage receiving assertions through a receiver crash instead. Its retained proxy owns the direct native receiver. After observing the exact generated source prefix, staged inode/hash, absent destination and zero receiving-validator calls, it signals only that still-unreaped receiver. It then writes one private release marker so the pinned external-copy fixture returns normally. The native initiating client must report/reap the external command with exit0 and an empty group, then report connection failure. The receiver must be genuinely reaped with SIGKILL. No producer PID from a counter is signalled.

The fake COPY/MERGE scripts additionally record their PID and process-group ID; the executor joins those counters to `external-process` records from the pinned production supervisor. This accounts for shell-mediated merge commands whose script PID can differ from their supervised group leader. All script replacements require exactly one original source match before use.

Normal transfer, user cancellation and receiver crash remain distinct evidence contracts. A crash is not validation success. The complete/partial original cases must still actually reuse the staged inode, validate before publication, discard rejected staging, recover with a fresh receive, and finish with an unchanged no-op.

Current evidence: `tests/qualification/current-named-producer-source-controls-actual-20261019.json` records 69 passing source-control methods (generated private stage files plus inert captures/handles/signals), not actual CLI calls or native interruption. Actor integration, full parent binding and actual stock/Ox runs remain outstanding. No production source or SDK transport was changed; no runtime admission or Photo hold exists for this successor.
