# Final private cross-volume qualification

The earlier `tests/cross_volume/qualification.json` is historical evidence. The
new `tests/final_volume_owner.py` will renew its twelve directed cases against
the current stock/Ox builds. It has not been executed as of this design entry.

The owner creates only a new 128MiB HFS+ image within its one-use private
workspace. Twelve cases cover both HFS→APFS and APFS→HFS, both compilers, generic
cloning enabled/disabled and DNG semantic cloning enabled. Each seeds, changes,
and verifies a 2MiB generated file, preserves an old hardlink, then requires a
true no-op. Unicode names are exercised. No SDK or actual camera input is used.
The same physical drive backs both logical volumes; this does not establish
independent physical devices, physical writes, or a performance advantage.

EX_GLOBAL is acquired before Unison00..07. All child commands use the retained
owner kernel with inherited canonical descriptors, real wait4/group census and
bounded observation. Every completed child and exact argv is persisted. Build
receipts bind current binaries and all production source inputs; artifacts and
frozen harness sources are checked again before each command and at completion.

No cleanup runs from a finally block after an attempted child. Unknown failure
retains the owner, leases, mounted image and raw evidence; there is no forced
unmount or broad kill. Only after all 36 CLI calls have settled does the owner
query the exact image path and mount point, validate the recorded image inode,
and issue normal detach for that owned mount. A fresh image census must prove
its attachment absent before release. Persistent system disk-image services are
not claimed as child groups owned by this test.

The fixture image and generated files remain for inspection. HFS+ coarse
mtime requires an explicit two-second generated-source edit advance. Existing
private-image receipts are preserved; this successor never reuses their paths.
Original contract controls reject foreign/duplicate image identities, wrong
mounts, filesystem type and whole-device identifiers without touching a disk.
