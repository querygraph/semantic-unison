# Camera-derived receiving control: prepared kernel only

`case.py` is not an executor, native clone implementation, or grant. Importing
it reads no input. There is no camera path default or standalone payload command.
[Seven actual tiny-fixture/mock controls](../qualification/camera-receiving-case-source-controls-actual-20261016.json)
passed under canonical Unison8, with actual outer terminal/group/token closure.
They do not use Unison, Adobe, a camera file, or EXglobal IO.

`clone.py` now defines descriptor-based native `fclonefileat` preparation with
no fallback. It fences the admitted readonly source epoch, holds the private
sender directory descriptor, refuses existing targets and inode aliases, and
makes only the new clone0600. Unknown descriptor closes use the existing shared
uncertainty carrier; a future executor must retain it. [Thirteen current controls](../qualification/camera-clone-preparation-source-controls-actual-20261016.json)
cover both modules using only tiny original data and a fake clone callback.
Fake callbacks explicitly report a test-double backend, never native success.
The actual native clone callback remains unexecuted by this qualification.

`transport.py` supplies a prepared fixed seed/update/no-op invoker with no
standalone entrypoint. It reuses bounded no-follow artifact hashing and the
qualified strict loopback measure wrapper, journals before/after each call,
and consumes a stage even when the call fails. Two workers per endpoint plus
two owner credits fit Unison8. Per-call timeout60s/native supervisor65s and
70s minimum remaining observation time are explicit; they do not establish a
whole-job hard wall. Update success additionally requires actual semantic
decline and one immutable receiver-basis clone marker, with no semantic or local
whole-source clone marker. [Twenty preparation controls](../qualification/camera-transport-preparation-source-controls-actual-20261016.json)
passed with mocked invocations and tiny original inputs only. The outer
admission/clone/execution/aggregate audit is still required before any real use.

`worker.py` now composes two serial same-compiler stock/Ox cases with a retained
borrowed-input descriptor, native epoch fencing before/after calls, one shared
invocation journal, and persisted partial case records. Its phase changes
irreversibly before transport may start; failures preserve their original
outcome rather than relabeling a missing result as no-start. [Twenty-three
preparation controls](../qualification/camera-worker-source-controls-actual-20261016.json)
pass using only tiny original fixtures and mocked boundaries. The worker has no
CLI/default camera input. Its eventual admitted entrypoint must retain uncertain
descriptor carriers and its parent must independently audit calls and aggregate
closure before release. Native clone and actual camera transport remain unrun.

`audit.py` now separates a complete two-case/six-call functional result from a
settled failed prefix. It binds journal calls to the admitted compiler and case
roots, matches each case's stored outcomes, checks exactness flags/digest scope,
and refuses conflicting failure/success claims. Zero-call failure is accepted
only in the pinned worker's pre-transport preparation phase; an empty journal
after possible dispatch remains unknown. [Twenty-eight current controls](../qualification/camera-result-audit-source-controls-actual-20261016.json)
pass on tiny original/mock fixtures. This pure audit does not prove aggregate
or parent exit, authenticate admission, grant payload reads, or close resources.

`execute.py` now defines the exact-admission parent/worker entrypoint. Its plan
must bind the fixed retained Unison clone, full readonly native identity, current
Python source closure, stock/Ox artifacts, short fresh workspace and declared
budgets. The parent delegates IO→CPU acquisition to the existing dispatcher;
there is no CPU-only camera route. The worker checks the live parent's START,
exact command and nine inherited descriptor identities before payload entry.
The dispatcher audits completed or failed-prefix receipts before aggregate reap,
then freshly checks the borrowed input's metadata before closing leases. Unknown
worker/FD outcomes retain ownership. [Current source controls](../qualification/camera-entrypoint-source-controls-actual-20261016.json)
pass, including scope/ancestry and pre-payload parent-binding refusals. The new
full inherited-resource lifecycle still needs disposable qualification; no live
camera plan or admission is created or implied here.

The next separately reviewed owner must provide all of the following before
this kernel can be used with the retained Unison-owned camera-derived clone:

1. Exact one-use source/admission/command/interpreter/artifact pins, source native
   epoch and historical SHA ancestry, unused private workspace, declared logical
   read/write budget, and bounded start/call/observation deadlines.
2. Existing EXglobal then Unison00..07 acquisition and partial rollback, inherited
   FD identity checks, actual group/server/pump settlement, and unknown retention.
3. One native clone-only sender with distinct inode inside that workspace.
   No full-copy fallback, hardlinks, original/Photo source reads, borrowed-input
   chmod/write/rename/unlink, or fresh borrowed-source SHA. Verify SHA only on
   the disposable clone; fence the borrowed source by metadata before/after.
4. A pinned `invoke` hook that records intent before every call, persists its
   returned outcome before verification, audits independent session groups, and
   selects the intended ordinary receiver-basis fallback. Observe its debug
   evidence explicitly; do not infer fallback merely from exact output bytes.
5. A persistent `save` hook and failure recovery that separates known nonzero
   settlement from functional success and never releases on absent processes or
   an observation timeout alone.

The case starts with the verified mutable sender and empty receiver. It seeds,
holds an old receiver FD, appends a bounded original synthetic trailer to the
sender, updates, and checks exact full-byte output/old-reader preservation and
an unchanged no-op epoch. It must not silently patch unknown private metadata.
Appending a trailer tests generic exact fallback; it is not a claim of valid
camera encoding, semantic editing, private-reference closure, Adobe validation,
decoded samples, or rendering equivalence. The full SOL.md corpus and optional
SDK receiving requirements remain open after any one such future control.

No payload execution plan or admission is issued by this directory. Retained
camera-copy ancestry is not consent to read it again. Future cross-compiler
cases and their aggregate IO budget must be fixed in a fresh reviewed plan.
