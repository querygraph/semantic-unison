These controls use an actual synthetic validator process that waits for an
owned gate file in a disposable retained case. No Adobe SDK, photograph,
preview, catalog, production volume, or performance benchmark is involved.

The standalone private vendored-Lwt copy watches the exact promise returned by the
endpoint execution wrapper. Two finite observer-installation exceptions are
injected after production native spawning has recorded the real child PID.
The parent control restores all listed production module inputs at commit
`2059949975ae95e64df74a3056d7211101aa42b6`; the fixture and private instrumentation
are identical to the fixed control. A designated failure requires an actual
live/unreaped child while validation or its workspace has already retired.

Fixed controls check Warn/Require and Off, normal and malformed receipts,
cancellation, late candidate/tool mutation, retained CPU/I/O/workspace
accounting, independent `waitpid(ECHILD)` reaping, first-error preservation and
queued workspace/device reuse. The late-mutation controls deliberately retain
no successfully captured process receipt after observer installation fails;
the immutable-input fence must still run. Gate presence alone never proves
child settlement. The pinned launcher is a synthetic Python script, so these
controls qualify invocation/settlement contracts rather than Adobe rendering.

The group fixture starts two independently gated real helpers concurrently.
A third synchronous launch failure or two observer failures on the first
recorded consumer must drain both. Releasing only the first child must leave
the aggregate pending with the second child's CPU/I/O/workspace held. The
parent group participant is the exact extracted legacy `Lwt_util.iter`
aggregation implementation; it is not a complete parent directory pipeline.

The standalone runner retains exact compile/link/test argv, exit status and log pins,
original/private source hashes, binaries and all case artifacts in its receipt.
`--negative-only` and `--fixed-only` select a single mode. This suite does not
claim a deadline under persistent allocation failure or an interrupted owner
event loop.

`receive.py` additionally rebuilds complete private compiler-matched Make
snapshots and drives actual Unison receiving/publication. Its private Files and
directory observer faults pause actual Identify domains after their native
input copies and CPU/I/O/workspace leases exist. Independent domains signal
owned readiness markers; the waiter hook uses bounded `Unix.select` observation
without pumping or reentering the legacy owner loop. Durable hooks at actual quarantine
and precommit record alive/unreaped children, actual running domains, candidate
existence, live destination bytes, admission totals and production archive-node
hashes. The fixtures retain old/live/archive bytes and decode the real format-23
archives to prove original full fingerprints survive rejection. Archive
container identity is observed separately because serialization metadata can
change. Concurrent directory controls require at least two actual domains;
these are not Adobe-child or end-to-end parallelism benchmarks.

5.5.1 and OxCaml 5.2.0+ox. Each compiler passed 28 standalone cases and 422
explicit assertions, with four designated parent failures. Actual Files
receiving passed three fixed cases and two exact full-parent failures per
compiler. Rejection retained the original live bytes/inode and typed archived

for retained binaries, source pins, argv, exits, logs and private artifacts.

Two initial receiving trials are retained. One fixed the new archive decoder's
local-open functor shadowing. The other removed a full-CLI helper-ready fault
case: the execution wrapper can return a queued I/O guard before child dispatch,
so a blocking child-ready observer would prevent that dispatch. It produced no
qualified case. Full receiving qualifies actual paused Identify domains; real
child settlement, unrecorded receipts and late mutations are qualified by the
standalone controls. No owner-loop pumping or substitute native dispatch was
used. Generic private execute-watch preparation is unexercised by the final
receiving case list and grants no additional claim. Follow-up standalone reuse
overwrites the gate's earlier ready marker; complete source/assertion/log proof
is retained, and an earlier numeric PID is not reconstructed from that marker.
