# Two-file SDK receiving successor: source preparation

This advances the required multi-file single-thread validation gate. It is not
an admission, an executor, or permission to reuse camera SDK V2. V2 is consumed
and proved two **serial** receiving seeds; it did not prove overlapping helpers.

`planning.py` checks a proposed two-candidate receiver envelope against the
production source/publication cost formula and standing Unison8 accounting.
`planning_test.py` checks seven finite boundary groups. The proposed settings:

- Two receiving candidates, three transaction slots (two Consumers plus Source).
- Per endpoint: `semanticpayloadbudget=6144`, `adobevalidatorworkspace=2048`,
  `validationtreememory=0`, `semanticdescriptorbudget=64`, `semanticmaxinflight=3`.
- Both loopback endpoints: three worker/helper credits each; two owner credits.
- Qualified SDK v1 single-thread tool only; two declared helper workspaces.
- Existing canonical EXglobal then Unison00..07 ownership; no new namespace.

The fixed maximum payload bound yields 134479872 Source bytes and2281963520
publication bytes per Consumer. Two Consumers plus Source require4698406912
bytes and56 descriptor credits. Two6GiB endpoint gates fit the standing32GiB
project reservation. These estimates exclude process baselines/native peaks;
no hard RSS, FD, CPU affinity or physical-IO cap follows.

Before any runtime request, a versioned executor must:

1. Bind fresh current stock/Ox binaries, all source/interpreter/tool and ancestry
   pins, a distinct workspace and a fresh explicit Root SDK/IO admission.
2. Use only two disposable native clones of the already admitted Unison-owned
   private copy per compiler; no original/Photo payload or fresh borrowed hash.
3. Perform one full two-file seed per compiler, serial compiler cases, exactly
   four qualified single-thread SDK calls total. No update/noop/retry fallback.
4. Persist call intent/outcome and retain every client/server/supervisor/pump,
   helper/group and aggregate owner until actual settlement. Missing proof or
   uncertain FD close retains ownership; deadline observations do not kill it.
5. Bind each candidate receipt and digest independently, full receiving SHA,
   borrowed source metadata fences, and all final CPU/IO descriptor closures.
6. Record two or more nonterminal observations per retained helper from the
   supervisor's common monotonic clock and actual PIDs. Bound live intervals by
   first/last nonterminal samples; spawn-to-observed-terminal times can overstate
   overlap because an owner may notice exit late. Two correct receipts alone do
   not prove overlap. If live spans fail to overlap, record a functional result
   and leave concurrency open.
7. Keep timing descriptive under shared8; throughput qualification needs its own
   controlled repeated workload. No semantic eligibility/pixel/corpus claim.

The next work is owner/protocol integration and finite fake-helper lifecycle
controls, then immutable review/admission. This document creates no runtime gate
beyond the existing coordination contract and grants no payload access.

## Interval evidence component

`intervals.py` is a pure auditor for exactly two independently bound single-thread
helper PID/candidate pairs and four common-clock monotonic-nanosecond events.
It rejects malformed, duplicated, incomplete, reversed or mixed-clock evidence.
Touching or serial intervals are valid evidence with `overlap_observed=false`;
only a positive common interval establishes observed overlap in these records.

[Eight original fixture groups](../qualification/sdk-overlap-evidence-controls-actual-20261016.json)
pass under the owned CPU lane. An initial wrong fixture expectation is preserved
and corrected separately. This component does not authenticate the timestamp
producer, prove actual helper concurrency, establish settlement, close FDs or
authorize resource release. Its output explicitly leaves those flags false.
Next integration must bind events to the actual supervised spawn/terminal
observations and separately audit all existing helper/group ownership proofs.

The production supervisor now offers optional `observe_alive` diagnostics at its
retained nonterminal child census. A separate original `/bin/sleep` component
control observes overlapping live spans and empty groups/direct reap on stock/Ox;
this is not yet connected to DNG validation or a qualified SDK event stream.
Default calls omit the observer and emit no live samples. Actual process lifetime
overlap does not establish simultaneous CPU execution or throughput improvement.

## One-shot invocation kernel

`invocation.Invoker` has no entry point or admission authority. Once an admitted
owner supplies its exact namespace, pinned binary/tool/copied scripts, journal
and observation deadline, it consumes its instance before any refusal/dispatch.
It rehashes artifacts under stable native epochs, records intent before the
strict-owned proxy call and persists a returned success or InvocationFailure
outcome before handing it to the worker. No automatic retry occurs.

Artifact hashing uses the already-qualified uncertain-close carrier, preserving
original errors and every uncertain FD identity without numeric retry.
[Seven source controls](../qualification/concurrent-invocation-kernel-controls-actual-20261016.json)
cover that path, changed pins, deadline refusal and journal/call ordering. They
use mocks and a tiny original artifact only. The future aggregate owner must
still bind the admission, inherit IO/CPU ownership, audit all helper/call groups
and retain unknown outcomes before this kernel may be used for actual receiving.
