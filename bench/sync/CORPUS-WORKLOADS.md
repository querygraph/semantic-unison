# Many-small, new-file and mixed corpus source contract

`corpus_workloads.plan` is pure metadata planning, not an executable benchmark.
It creates no file, reserves no CPU/IO and always returns dispatcher_ready=false.
The current single-file CLI does not accept these corpus workload names.

Defaults are4096files ×32768bytes =128MiB generated target content. Bounds are
1024..16384files,32768..262144bytes/file, and8GiB declared total. Payloads remain
arbitrary generated bytes, not photographic or SDK-valid images. Paths group64
files per deterministic directory. Source/reference counts are exact:

- many-small: all files exist at seed, then each gets a fixed-length XMP edit;
- new-files: no source or receiver file exists at seed; create donors only after
  seed, with no fabricated receiver basis or metadata-merge expectation;
- mostly-eligible-mixed: every full20-file group contains16fixed-XMP updates,
  one metadata+raw update, one metadata+opaque update, one unsupported-signature
  update, and one newly added file. An incomplete tail is selected deterministically.

A4000-file original metadata control proves3200predictedSDE updates,600fallback
updates and200additions. These are expected dispatch classes, not observed Unison
paths. Actual peer/capability/format refusal must remain visible in later results.

## Required separate batch consumer

Do not raise the old runner's256-file limit and reuse it blindly. In addition
to adding generated seed indexes above255, a batch consumer must provide:

1. An independently pinned per-sample fixture inventory, bounded before creation,
   recording all donor/base/expected target identities and absent-before additions.
   No shrinking to fewer files after resource refusal.
2. Per-call raw stdout/stderr/supervisor artifacts with exact SHA/byte pins and
   explicit capture bounds. Keep complete raw evidence, but store references in
   aggregate results instead of embedding thousands of traces repeatedly. Capture
   overflow refuses qualification; it must not become silently accepted truncation.
3. Bounded recursive inventories for all grouped paths, exact target hashes and
   unchanged receiver-basis/open-reader checks. No-op verification must cover every
   receiving file, not just root directory entries or aggregate counts.
4. Per-class path counts: eligible updates, exact fallbacks and new whole-file
   receipts are separate. A mixed row cannot inherit the old all-files-SDE assertion.
5. Actual durable call intents, independent client/server/group settlement and
   qualified descriptor closure, using EXglobal then standingUnison00..07. Unknown
   retains ownership and prevents new calls. No CPU18borrow by default.
6. Warmups plus at least five measured repetitions and raw timing disclosures.
   Directory creation, hashing, fixture generation and cleanup must be labeled
   separately from synchronization; no physical-write or cold-cache inference.

## Bounded artifact source successor

`batch_artifacts.py` publishes byte-exact stdout/stderr or serialized inventory
bytes through the existing qualified immutable Store. Each artifact is limited
to4MiB, split into256KiB base64 JSON chunks below Store's2MiB record bound;
aggregate evidence contains only chunk size/SHA references and a whole-byte SHA.
Empty streams are explicit. Overflow, tampering and false lengths refuse; no
truncation or UTF8-replacement round trip is accepted. Publication errors retain
partial files and propagate the original ownership carrier without cleanup or
numeric FD retry. Store/process/resource ownership remains with the caller.

## Sample phase composition

`batch_sample.sample` now composes the exact canonical unshrunk corpus:
seed creation and seed inventory → donor/empty receiver verification → seed
transport → both seed replicas verified → edits and source-only additions →
pinned target inventory → update transport → both targets verified → no-op
transport → both targets verified with identical receiver eight-field identities.
It stops on the first exception, preserves partial files, never retries and
never closes caller-owned resources. Both roots must initially be distinct,
empty, absolute0700owned directories. Canonical corpus equality refuses shrinking.
`verify_expected` handles seed expectations separately from changed-target
inventories, including the explicit empty seed of an all-new corpus.
