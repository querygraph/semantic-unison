# Additional SOL workload recipes

`workloads.py` is a pure generated-container recipe library. It opens no path,
creates no fixture, executes no Unison process and grants no IO. The existing
`fixtures.py`, frozen cohorts and their completed result bytes are unchanged.

Its synthetic Classic TIFF header declares distinct primary encoded payload,
JPEG-interchange preview, XMP and complete remaining opaque bytes. Payloads are
arbitrary, not valid photographic encodings or SDK qualification inputs.

| Recipe | Independent byte effect | Expected path, not an observed result |
| --- | --- | --- |
| fixed-xmp | Same-sized packet replacement only | SDE-eligible generated shape |
| growing-xmp | Increase packet size, append new packet, update count+pointer; preserve every old payload byte | Exact fallback because extent/size changes |
| metadata-preview | Replace XMP and XOR one declared preview byte | Exact fallback because protected complement changes |
| metadata-raw | Replace XMP and XOR one primary encoded byte | Exact fallback because protected complement changes |
| metadata-opaque | Replace XMP and XOR one unclaimed gap byte | Exact fallback because protected complement changes |

`initial_writes(layout)` overlays a separately streamed deterministic noise
source. `recipe(layout, kind)` returns immutable, nonoverlapping byte actions and
an exact target size. XOR actions require reading only that generated byte.
No receiving clone, in-place editor for real TIFFs, or general TIFF serializer
is supplied. The consumer owns all source/destination paths, permits and hashes.

Six original in-memory controls independently decode the header and check exact
changed-byte sets, append geometry, preservation, bounds and forged contracts.
They are not parser acceptance tests or timings. See
`tests/qualification/generated-workload-recipes-actual-20261019.json`.

## Next integration and outstanding workloads

The benchmark runner does NOT consume these recipes yet. Add a versioned owned
consumer and source-qualified CLI/plan field; preserve existing default fixture
bytes. Independently hash the final generated donor and received file; keep the
old receiver/basis unchanged and verify no-op inode behavior after receiving.
Record source/target sizes separately, especially when XMP grows. Strict SDE
success expectations must remain for fixed-XMP cohorts; fallback workloads must
be reported as fallback, never silently counted as semantic acceleration.

No-change/new-file, full-content replacement, thousands of small files,
malformed/unsupported mixes, concurrent editor and mostly eligible mixed corpus
still require their corresponding workload designs/execution. Same/cross-volume,
non-APFS and actual network/cold-cache scopes remain separate. At least five
measured repetitions after declared warmups remain the SOL benchmark contract.
Larger sizes alone do not replace these workloads. Do not start any IO until the
current Photo window is released and the new exact owned run is coordinated.
